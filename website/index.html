Project update

Tests and security checked for BMEC 0.9.1-beta.3.

Checked 2 October 2026 · 18:44 EEST

Software checks

The full suite passed: 1,278 tests, with 7 skipped (133 test files passed; 2 skipped). Native differential checks passed all 75 cases; fuzzing passed 12 properties. Documentation coverage, package install, examples, application/browser behavior, and accessibility automation passed. Documentation, package install, examples, and real-browser website checks also passed at phone, tablet, and desktop sizes. Accessibility scans reported zero violations.

Security checks

The automated security gate found 0 known dependency vulnerabilities, generated a CycloneDX lockfile SBOM with 177 components, and checked all 133 release files for source, test, and secret paths.

Scope: These are automated checks, not an independent penetration test, hosted production security audit, or certification. BMEC remains a developer beta. Human onboarding and a real screen-reader session have not been performed. A production operator must provide HTTPS, trusted origins, secret storage, backups, monitoring, and application-specific authorization.

Architecture and trust

Know what BMEC checks—and what your host owns.

Authentication is separate from row authorization. Origin rules protect browser writes, but TLS and proxy identity belong to the host. The database adapter does not add ownership predicates on your behalf.

Compiler architectureSecurity limitsThreat modelDeployment requirementsCapability coverage

Validation boundaries

  • Windows and Linux have local candidate checks.
  • macOS is not validated.
  • No independent security audit or production certification is claimed.
  • Native compilation supports a documented subset.
