Measure a named workload on a named machine.

BMEC keeps benchmark claims tied to a repeatable command, workload, runtime version, and machine. Local measurements describe that setup; they are not a promise of hosted performance.

Run the standard gate

Build BMEC, then run the maintained performance gate against its local SQLite and PostgreSQL fixtures.

npm run performance:gate

Inspect the workload

Use the benchmark command for the compiler and runtime workload suite. Save the JSON output with the machine and Node.js versions.

npm run benchmark

App-level browser workload

The Community Issues browser run seeds 135 local issues across the selected and a foreign repository, checks 126 search matches, runs real Chromium interactions, and samples bounded concurrent authenticated reads. Repeat UI searches and request waves with BMEC_APP_PERF_UI_REPEATS, BMEC_APP_PERF_CONCURRENCY, and BMEC_APP_PERF_CONCURRENT_WAVES (maximums: 20 repeats/waves and 32 concurrent requests). Run the SQLite fixture with npm run test:community-issues-browser. To measure PostgreSQL, set BMEC_APP_PERF_DATABASE=postgres, BMEC_POSTGRES_URL, and the explicit BMEC_POSTGRES_DISPOSABLE=1 opt-in; the test creates and drops a random isolated schema.

Each benchmark CRUD sample performs insert, read, update, and delete as separate adapter calls. Those four calls are not wrapped in a transaction. The app-level timings include runtime startup, actual HTTP requests, browser UI actions, and concurrent requests; they are local workload measurements, not service-level objectives.

Keep execution modes separate

  • Reference/interpreter: reports the BMEC interpreter workload in the benchmark JSON; it is not a compiled-native result.
  • Native: reports workloads compiled through BMEC's generated C backend. Native differential correctness is separate from speed measurements.
  • Node.js/C++ comparisons: available only for named comparison workloads with their own commands and environment; they do not support a general-language ranking.

Reproduce the homepage interpreter ranking

Run npm run benchmark:interpreter-ranking on Node.js v24.18.0 and Windows x64 for the displayed comparison. It compiles four fixed BMEC workloads, warms each once, and measures five executions of 200,000 iterations. The aggregate before-times are in docs/interpreter-workload-baseline.json; results on another runtime, platform, iteration count, or sample count are reported without a reduction ranking.

Every result is workload-specific. Do not combine interpreter, native, browser, or database numbers into one ranking. PostgreSQL measurements depend on the local database and network path; browser and native measurements use separate harnesses.
